今回の配置見直し
- 配置図: outputs/review/signal-flow-placement.png（実際のKiCad配置と概念的な信号ブロック）。
  outputs/review/placement-front.png は表示器装着状態、rp2040-closeup.png は拡大図。
- RP2040中心(32,31)、270度。GPIO0..7のデータ端子が上の音源IC側を向く。
- 6N137を中心(20.75,41.25)に移し、左のMIDI入力とMCUをつなぐ配置にした。
- 水晶はMCU左、QSPIフラッシュは右。フラッシュのCLK端子をMCU側へ向けた。
- USB-C中心(34,50.35)、開口は基板下端の外側。ESDは(41.5,49)、直列27ΩはMCUの近く。
- CVの100k/10k、クランプ、フィルタをTLV9004入力近くに集め、ADS1115を隣接させた。
  CV1ジャックから右の共通バッファまでは長くなるが、減衰抵抗より前の区間とし、
  高インピーダンスの測定ノードを引き回さない。配線時にクロック／電源SWとの並走を避ける。
- 左右ゲートの保護・トランジスタ・プルアップは各ジャック脇のブロックにまとめた。
- ミキサーは右のLINE OUT寄り。帰還抵抗・並列コンデンサはアンプ入力・出力の近く。
- 昇圧回路は左上に移し、右のCV測定回路・ミキサーから離した。
  SW端子〜インダクタ端子のマンハッタン距離は3.96mm→1.79mm。
- MCUのクロック直列抵抗R26/R27は送信側に配置。GNDを切らない短い配線を優先する。
- 音源ICの100nF/4.7µFは3個とも同じ並び。MCU下の電源コンデンサは3列×2段に整列。
- outputs/review/flow-metrics.json に見直し前後の幾何学的な比較を保存。
  各ネットの端子中心を結ぶマンハッタン最小全域木の合計。実配線長ではなく、
  基板障害物、層変更、GNDリターン、信号干渉や配線後の性能は評価していない。
  MIDI受信→MCU: 61.67→18.38mm（70.2%減）、CV高インピーダンス部分:173.38→39.79mm（77.1%減）、
  CVバッファ→ADC:143.94→27.69mm（80.8%減）、ミキサー帰還等:88.80→36.17mm（59.3%減）。
  USB信号合計:84.26→61.15mm（27.4%減）、データバス合計:665.20→620.98mm（6.6%減）。
- 配置検討時はDRC 0、ERC 0、配線・ビア0、未配線項目376だった。現在の配線検査値は最終DRCレポートを参照。全体の最短配線を証明した設計ではない。
- 全152フットプリントの最終座標をlayout_targets.jsonに固定。
  回路生成からの再構築で座標・向き・実装面がすべて一致することを確認した。
- 配線ではUSBの連続したGND基準・ペア配線、電源SWの局所ループ、水晶のGND、
  CV測定点とミキサー帰還の局所配線を優先。必要なら承認配置からの微調整を再提示する。

電源／USB
- 電池・電源スイッチ・USBホスト給電・役割切替制御を削除。USB-C給電とUSB MIDIデバイス。
- USB-C CC1/2 は各5.1kΩ RdでGND。100kΩ/100kΩ分圧＋100nFでRP2040 ADC26/27にも接続。
- AP2120N-3.2TRG1 (C6500828): pin1 GND / pin2 VOUT / pin3 VIN。3.2V±2%の共通ロジック電源。
  OLEDモジュールのデータシート上限3.3Vを越えないため、3.3V±2%品を避けた。
- TPS61023 (C919459) は電池昇圧用ではなくUSB電圧低下時の音源用5V確保に使用。
  R7=22k/R8=3kで5.0V。VIN>VOUTのパススルーモードもICの電源許容範囲内。
- GPIO29 SOUND_ENABLE: 未構成時は5V音源を切り、データ・制御・クロックをLow/Hi-Zにする。
  USB構成後、音源電源を有効にして初期化／消音。その前にクロックを止める。
- ファームウェアではUSB2.0 bMaxPower=250（500mA）を要求する案。
  未構成時100mA以下、サスペンド時の音源OFF・表示OFF・MCU低消費処理が必要。
  実際の起動電流、OLEDモジュールの入力容量を含む突入電流とサスペンド電流は実測し、
  必要ならロジック電源へスルーレート制御スイッチを追加する。USB適合検証済みとはしない。
- USB-C充電器単独でのCV演奏はCCの供給電流広告検出で有効化する方針。
  閾値・デバウンス・通常電流広告のUSB-A充電器への対応はファームウェア段階で確定する。
- USB MIDI鍵盤の直接ホスト接続は廃止。TRS Type A MIDI INは維持。

音源・オーディオ
- SAA1099 DIP18、SN76489AN DIP16×2は支給部品／ソケット後実装。
- 音源バスはD0..D7、WR、3個のCS、SAA A0、SAA DTACK。
- SN76489ANのD0は最上位ビット。SAA端子とMCU GPIOの接続順序を合わせ、GPIO0..7のポート書込みは論理バイトをそのまま出力する。個別PIN_Dn書込みではreverse8を使う。
- SAA clock=8MHz、SN clock=4MHz、RP2040 sysclk=128MHzを想定。
  SN READYピンは未接続。SN書き込みには32clockを越える10µs以上の待ちを入れる。
- SN tone = clock/(32N), N=1..1023。4MHz時の最低周波数は約122.2Hz。
  CV音程設定にはこの下限と整数分周の音程誤差を表示／クランプすること。
  低音向けの音色はSAA1099への割当を基本とする。必要ならSNクロック変更を別途検討。
- ミキサーは実ICのアナログ音を合成。SAA L/R、SN1左、SN2右。
  「混ぜ方」はレイヤー音量・音色・ノート割当。SNの自由な左右パンには別のアナログ回路が必要。
- TLV9004IPWR、AC結合ステレオライン出力。外部アンプ等10kΩ以上の入力向け。
- PCM5102なし。ヘッドホン用アンプなし。MIDI出力用TRSジャックもない。

CV／ゲート
- 左列 CV1 / GATE1 / MIDI IN、右列 CV2 / GATE2 / LINE OUT。各ジャックは同じY=19.5/31/42.5。
- CVは1V/oct、2系統独立。0V基準ノートをUIで設定する。
- 入力は100kΩ→ノード、ノードは10kΩでバッファ済みVCC/2へ接続。
  別の100kΩ/10kΩで10/11×VCC/2を作り、差動ADCで引く。公称ADC差動入力=CV/11。
- 抵抗は0.1% (100k C855559、10k C95204)。TLV9004でCV1、CV2、基準をバッファ。
- BAT54S C83935: pin1 GND、pin2 +3V2、pin3入力ノード。100nF入力フィルタ。
- ADS1115IDGSR C37593、VSSOP10、I2C 0x48。AIN0–AIN1、AIN2–AIN3を交互に差動測定。
  PGA±2.048V、860SPS。2ch合計860SPSで、1ch最大430SPSより通信・画面処理分だけ低下する。
  音程／低速変調向け。オーディオレート変調を想定しない。
- 0V・1Vの2点校正を系統別に保存。抵抗公差、オペアンプoffset、ADCgainを校正する。
  分解能の公称値は入力換算約0.6875mV/LSB ≈0.825cent/LSB。実機の精度保証値ではない。
- 動作電圧と1%バイアス分圧を含め、CV±12Vではノードが電源範囲内に収まる設計。
- ゲート0–5V／0–10V。MMBT3904-7-F C94514に100k直列＋100kベース抵抗、逆BE保護ダイオード。
  コレクタは10kで3.2Vへプルアップ。RP2040入力はActive Low。ゲート閾値／遅延は実機で測定。
- 2.2kのロジック電源ブリーダーでUSB未接続時のCVからの注入電流を逃がす。
  大電流ESD／誤配線耐性まで実証した設計ではない。

表示器／操作
- HS96L03W2C03 (C5248080)、0.96インチ128×64白OLED、SSD1315、I2C 0x3C。
  接続: GND/VCC/SCL/SDA。3.2V給電。OLEDとADS1115でI2C1(GPIO18/19)を共有。
- −／決定／＋の3個のC318884ボタン。X=48/57/66、Y=50、9mm等間隔。
- 短押し：移動・選択・値変更。−長押し：戻る。＋長押し：全音停止。
  保存はPRESET→SAVEで明示実行し、フラッシュ寿命を避けるため毎編集時には書かない。
- MIX：SAA/SN1/SN2/Master。CV/GATE1・2：音源の声・音色・0Vノート・包絡・有効/無効。
  MIDI：USB/TRS各チャンネルと割当、TRS→USB MIDI転送、CV声の予約／競合規則。
  PRESET：8枠保存／読込／初期化。CAL：CV1/2の0V/1V校正。
- NOISEなど非音程音色ではCVを周期／音色変調へ割り当て、1V/octを無理に適用しない。
  表示に使えるVOICE候補は選択した音源の機能に応じてファームウェア側で絞る。
- CV声を予約した場合、MIDI allocatorはその声を使わない。
  LAST NOTE設定では最後の入力を優先して、ゲートとNote Offの対応を独立して追跡する。
- OLED描画は低頻度に分割して送信し、CV取得やゲート割り込みをブロックしない。
- BOOT/RESETは裏面銅パッドJP1/JP2。短絡操作用、日常操作ボタンとは分離。
  BOOTは短絡を保持しRESETを短絡して解放するとUSB書き込みモードになる。
- 空きGPIOは23・24の2本。現在は未接続。

取り付け
- OLEDモジュール本体27.3×27.8mm、中心(42.5,31)、四隅穴(±11.65,±11.9)、穴径2.5。
- 4ピンのYはモジュール上端から1.32mm。ピンピッチ2.54mm。
- モジュールの基板下面とメイン基板表面との間に5mmのM2スペーサー。
  モジュール裏面の最大部品高さ1mmを差し引いても、下に置いたMCU／フラッシュ等は収まる。
- ネジ頭／スペーサー用に直径4.1mmの領域を確保。表示器本体は浮かせるためDwgs.Userで表示。
  キーとジャック／ソケット／USBは表示器本体の投影範囲外。
  投影範囲内のSMT部品の高さと取り付け公差は現物照合が必要。
- モジュールは手実装。4本の接続ピンは有効長8mm以上の長ピン、または短い配線を使用。
  JLCPCBは基本的にメイン基板表面のSMT部品を実装。裏面JPは銅のみで部品なし。
- モジュール・ソケット・ピンヘッダ等の実装可否／部品在庫／実装費はPCBA見積もりで確認。
- シルクは配置／配線確定後に整理する。配線前のレンダリングは完成基板の写真ではない。

共有データバスの配線時変更
- SAA1099の物理D0(pin10)..D7(pin17)は基板D7..D0へ逆順で接続し、
  SN76489ANの端子列と共有バスの物理順序を揃えた。
- GPIO0..7を基板D7..D0へ割り当て、物理的なバスの順を揃えた。
- SAAのアドレス設定・データ書き込み、SNの全バイトはGPIOポートへ論理バイトを直接出力。
  個別PIN_Dn書込みではreverse8を使う。両APIをfirmware/sound_bus.hに定義。
- GPIO0..7内のデータ線の順序を変更。他のGPIOと部品の座標・外形は維持。
