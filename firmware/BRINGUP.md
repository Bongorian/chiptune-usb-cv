# v0.8.1 初回動作確認

PC上のレジスター・状態・保存検証と、実基板での測定を分けて記録します。配布UF2はalpha版です。v0.8の発音、OLED、Android更新、電源断からの保存復元は未確認です。

## 更新と最小試聴

この版は旧音色・セットアップ・ルート・パターンをRAM内で新構成へ移行します。起動時の自動保存はありません。CV校正と明るさは保持します。フラッシュの実際の書込と電源断復帰は実機確認が必要です。

1. [UF2](dist/chiptune-v0.8.1-alpha.uf2)をRPI-RP2へコピーします。完了後にUSBを抜き、ボタンを押さずに再接続します。
2. ホームにCH1 SAA TONE / CHIPLEADが表示され、OK長押し → SYSTEM > VERSIONがV0.8.1 ALPHAであることを確認します。
3. J3（右下LINE OUT）を外部アンプへ接続し、MIDI ch1のC3とch2のE3を同時に保持します。ch1を離してもch2が鳴り続けることを確認します。
4. ch3のSNステレオ2声とch10のノイズを追加し、各ノートの所有元・左右・音色を確認します。
5. OK長押し → EDIT CHANNELをCH2へ変えてもch1が停止しないこと、音色選択が各チャンネルの音源役割を越えないことを確認します。
6. ノイズをMETALへ変えてもch1〜3の保持音が停止しないことを確認します。SNクロックFXの操作は、物理的に共通なのでch3/ch10両方へ影響します。
7. 起動後、音色・全パート設定を保存して電源を入れ直し、二回目の初期化が起きないこととCV校正が保持されることを確認します。

## 起動停止からの復旧

v0.8.0の初回保存でSDKのフラッシュ容量チェックにより停止する問題を修正しました。[BOOT_RECOVERY.md](BOOT_RECOVERY.md)の手順で更新し、USB MIDIとOLEDを個別に確認します。設定領域の全消去は不要です。

## OLED復旧の確認

v0.5.0ではMacでUSB MIDIとして認識されてもOLEDが表示されず、v0.4.0に戻すと表示が戻る報告があります。v0.5.1ではCV処理の重複を減らし、OLED/ADCに最大4msのサービス待ち時間を設けています。

- コールド起動、UF2書き込み直後、USB抜き差しで表示されることを確認します。
- CV/Gate未接続・接続、MIDI発音中でも画面とボタンが更新されることを確認します。
- MacのUSBスリープ復帰後にも明るさと画面が復旧することを確認します。
- 修正版の実機での表示復旧は確認待ちです。PCでの転送・負荷・再試行テストと区別します。

## UI

- ホーム−/＋の音色選択、短いOKの音作り、長いOKのメニューを確認します。受信元・MIDIチャンネル・発音数が実際の入力と一致することを確認します。

- −/＋、短いOK、OK長押しを全ページで操作します。編集確定・取消・階層の戻り、長押しによる数値の加速を確認します。
- 音源資源が足りない声数を試し、拒否されて既存構成と発音が保たれることを確認します。
- 試聴を続けながらOSC、AMP、マクロを編集します。シーン/音色の保存確認でNOを選んだ場合に変更しないことも確認します。
- SOURCE/GATE/パターンの名前と実際に操作されるパートが一致することを確認します。
- 資源画面のA〜N、K、空き、発音中の点を照合します。波形図は模式図です。

## SAA1099

- SAA TONEの基準音程、左右PAN、ADSRを確認します。
- ENV OSCをC2/C3/A4で測定します。16ステップ三角、8ステップ三角、下降、上昇で基本周波数を測り、切り替え時の換算を確認します。三角波は鋸歯状波の倍のカウンター長です。
- FE/NEを無効にしてENV自体が出ていること、クロック用チャンネル2/5（1始まり）が無音であることを確認します。
- 高すぎるENVノートが無音になること、KEY RESETとFREE、単発形、R INVERTの左右関係とモノラル合成を確認します。
- SAA AMではキャリアとENV用クロックの比、ソフトADSRの独立を確認します。
- 異なるノイズ色のパートを両群へ配置し、別パートのノイズ色を変更しないことを確認します。

## SN76489AN

- v0.6.1のKEY TRACKホワイトノイズは更新クロックを音程の32倍にします。旧MULTIのch10 D2で、修正前の低速な段差音からノイズの帯域が変わることを聴取・測定します。この変更が報告された症状と同じ原因かは実機確認が必要です。
- FAST/MID/SLOWの固定レート、ホワイト／周期、左右単独／両側、通常トーンとの同時出力を個別に確認します。HI HATは短い減衰音なのでREPEATを使います。

- SN LEFT/RIGHT/TWINを聴き分け、左右のデチューン・バランスを確認します。
- 基準4/2/1MHzと、実クロック250kHz〜4MHzの周期・約50%デューティを測定します。SAAは8MHzを維持します。
- 固定ノイズ3レート、Tone 3追従、周期ノイズ、白色ノイズ、METALのTone Mixを確認します。周期ノイズの音程はANの分周比を前提としているため、実チップで測定します。
- FXをOFF/DIVE/TRIANGLE/RANDOM/SEQUENCEで変更し、両SNの全声が共通に変化することを確認します。
- 低速クロック時のWE LOW幅（最大136µsの待ち）、書き込み取りこぼし、MIDI負荷時の安定性を測定します。

## MIDI・CV・Gate

- USB/TRSを同時接続し、同音連打・重複Note On/Off・サステイン・ピッチベンド・RPN0・プレッシャー・MONO/LEGATO復帰を確認します。
- レイヤー/スプリット、Program Change、マクロCC16〜19、クロックCC20〜31、TRS→USB転送を確認します。
- 0V→1Vの順で両CVを校正し、SAVE CALします。0/1/2Vで音程を測定します。
- Gate 0–5V/0–10V、個別のNOTE/RETRIGGER/STEP/FX、CVスケール・グライド・変調の符号を確認します。
- MIDIが保持中のCV声を奪わないこと、ADC異常時にCVノートが止まり変調が外れることを確認します。
- PANIC後、Gate Highのまま再発音せず、Low→Highで復帰することを確認します。

## 保存・電源・更新

- シーン、音色、名前、校正を保存し、電源再接続して復元を確認します。
- v0.4〜v0.7の校正を持つ基板でv0.8へ更新し、校正値を引き継ぐことを確認します。旧演奏設定はch1/2/3/10の新構成へ初期化します。
- 保存の電源断試験を行う場合は、事前に設定をバックアップし、片方のコミット済みバンクが残ることを確認します。
- USB未構成/サスペンド時の音源電源OFF、GPIO Hi-Z、OLED/LED OFFと電流を実測します。1.5A以上を広告するUSB-C充電器での単独CV/TRS動作も確認します。
- AndroidでBOOTSEL、WebUSB許可、UF2更新、通常起動、MIDI再接続を確認します。

I2CはOLED=0x3c、ADS1115=0x48です。音源ICのDTACK/READYによる存在確認は行いません。IC未装着を音源検出済みと表示することはありません。

評価記録には基板リビジョン、IC刻印、OLED型番、UF2のSHA256、ホスト/端末、電圧/電流、音程誤差、最大処理時間、USB/ADCの状態を残します。
